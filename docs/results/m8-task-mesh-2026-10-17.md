# M8 task/mesh shading: initial native tranche

Date: 2026-10-17. Implemented Linux Vulkan profile, not M8 completion or Metal parity.

## Contract and implementation

- Independently requested `MESH_SHADER` and `TASK_SHADER`: mesh requires raster;
  task requires mesh. Availability is queried, never silently enabled. Devices
  without the extension retain the existing baseline and load no mesh commands.
- `QUERY_MESH_LIMITS` exposes separate task/mesh launch and local-size limits,
  shared/payload/output budgets, output counts, allocation granularities and native
  preferences. Physical limits do not imply feature enabling. The exact query has
  the same caller-storage/schema rules as other foundation queries.
- Graphics executables accept mesh with optional fragment, or task+mesh with
  optional fragment. Vertex and mesh families cannot be combined. Existing graphics
  state, argument interfaces, heaps and render scopes remain the model. Mesh output
  topology belongs to the artifact; vertex-input state is absent.
- `MESH_REQUIREMENTS` replaces ordinary shader requirements for these executables.
  The artifact producer supplies post-specialization workgroup, shared/payload and
  output facts. OGPU checks limits, not SPIR-V semantics. Output bytes use native
  padded accounting, excluding primitive index arrays; they are not packed C sizes.
  See [native mesh output accounting](https://docs.vulkan.org/spec/latest/chapters/VK_NV_mesh_shader/mesh.html)
  and [mesh properties](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceMeshShaderPropertiesEXT.html).
- C `ogpu_next_draw_mesh` / `ogpu_next_draw_mesh_indirect` and corresponding direct
  Rust functions use the existing recording/error model. Direct launches check the
  applicable entry-stage limits. Indirect records are three u32 dimensions and
  reuse explicit argument/count spans. Dimensions and task-emitted mesh work are
  trusted execution-time obligations; no CPU scan, clamping or readback.
- Direct lowering is one native mesh draw. Indirect/count lowering shares ordinary
  draw range validation and uses the modern address-based commands, with no legacy
  buffer-handle path. See [native address-indirect mesh drawing](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdDrawMeshTasksIndirect2EXT.html).
- Mesh/task synchronization scopes and subgroup discovery are represented. Optional
  subgroup size/varying controls use the existing per-stage contract. Full-subgroup
  enforcement remains compute-only in this implemented profile. Incompatible active
  vertex/geometry/clipping/tessellation statistics reject mesh draws; caller/native
  rules still govern inherited queries and shader/attachment compatibility.

Preparation may allocate/compile, as before. Recording adds no allocation,
resource-retention walk, compiler, hidden barrier or mesh-to-vertex emulation.
This preserves the existing native strategies; it is not a performance measurement.

## Evidence

Pinned Slang 2026.14.1 reproduces four checked-in SPIR-V artifacts and all pass
`spirv-val --target-env vulkan1.4`. The shader source follows Slang's native
[task and mesh stage syntax](https://docs.shader-slang.org/en/stable/coming-from-glsl.html#amplification-shader-task-shader).

`examples/foundation_mesh.h`, included in `cargo xtask foundation`, checks:

- mesh-only and task+mesh executables with a fragment stage;
- direct, padded multi-draw indirect, GPU-count-selected draw, zero count,
  zero direct work, count clamping to maximum and zero fixed draw count;
- all 896 RGBA pixels, including cleared outputs for no-work cases;
- task payload transport: the task stage swaps color channels and only its payload
  supplies the mesh color, distinguishing this path from direct inline consumption;
- unchanged argument/count bytes and surrounding readback guards;
- invalid local size during preparation and five poisoned-recording cases:
  missing render scope, over-limit direct dimension, conventional draw on a mesh
  executable, short indirect span and invalid stride.

Results with Vulkan validation and synchronization validation enabled:

| Local driver | Result |
| --- | --- |
| Radeon RX 5700 XT / RADV | Mesh/task unavailable; explicit rejection/discovery checked; existing full foundation regression passes. No mesh execution claim. |
| llvmpipe 26.2.1 / LLVM 21.1.8 | Both features enabled; `MESH_PASS variants=2 modes=7 pixels=896 guards=1 rejected=5 task_payload=1`; foundation regression passes with the existing combined depth/stencil-copy exclusion. |

The llvmpipe run uses `OGPU_FOUNDATION_STENCIL_RASTER_ONLY=1` for the unrelated
existing combined depth/stencil plane-copy issue. Mesh color/payload/readback checks
are not excluded. No validation errors were reported by the fixture harness.

Host coverage includes feature dependencies, stage composition/order, separate and
combined limits, launch arithmetic/overflow, mesh indirect record sizes, scope/access
mapping, exact query layout and C/native-Rust surface correspondence. Native discovery
tests also cover disabled/mesh-only/task+mesh enabling where supported and failed
public creation outputs. ABI comparison covers 1,207 layout values.
The final run passes 64 host unit tests plus two native-Rust surface checks,
20 headless native tests on each driver, Clippy with warnings denied, C11/C++17
combined-header syntax, formatting and pinned binding/shader reproduction.

## Remaining proof and next work

- No physical GPU here supports this mesh profile; llvmpipe is native Vulkan execution
  evidence, not hardware throughput, mesh scheduling or cross-vendor acceptance.
- This fixture uses host-authored indirect records/counts. GPU-produced arguments,
  culling/identity, task amplification beyond one emitted group, shader roots/heaps,
  specialization/subgroup variations, secondary lists, replay and mixed vertex/mesh
  draws still need mesh-specific consumer coverage.
- Mesh-specific query counters, multiview mesh and primitive shading rate are not
  enabled. Their native feature bits remain off, even if reported physical limits
  are nonzero. Output-layer limits do not imply arbitrary other raster profiles.
- Next implementation batch: native generated-command layouts, executable selection,
  explicit preparation/storage and execution. Then integrate a GPU-culled scene and
  remaining advanced raster profiles. No hidden command expansion or CPU readback.
- Metal foundation work stays deferred; source-level Linux tests do not validate it.

The public revision remains experimental. Rebuild consumers against matching
sources; this tranche is a coherent extension of the current contract, not an ABI
freeze or a claim that every mesh-shader interaction is accepted.
